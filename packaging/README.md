# kindling distribution

This directory holds the native-binary distribution artefacts for the `kindling`
umbrella binary. They are consumed by end users through four channels. The
binary is cross-built once by the reusable
[`_cross-build.yml`](../.github/workflows/_cross-build.yml) workflow (all 7
targets, packaged as `kindling-<version>-<target>.tar.gz` + `.sha256`), and
[`release.yml`](../.github/workflows/release.yml) attaches those archives to the
**GitHub Release**.

| Channel                | Artefact in this repo                                                                                            | What the user runs                                                                      |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| crates.io              | `scripts/publish.sh` (order), vendored `crates/*/schema/`                                                        | `cargo install eddacraft-kindling`                                                      |
| `curl \| sh` installer | [`install.sh`](../install.sh) (repo root)                                                                        | `curl -fsSL https://raw.githubusercontent.com/eddacraft/kindling/main/install.sh \| sh` |
| GitHub Release         | [`release.yml`](../.github/workflows/release.yml) (archives + VSIX)                                              | Download from [Releases](https://github.com/eddacraft/kindling/releases)                |
| Homebrew (macOS/Linux) | `packaging/homebrew/kindling.rb` → [homebrew-tap](https://github.com/eddacraft/homebrew-tap) (shared with anvil) | `brew install eddacraft/tap/kindling`                                                   |

> The CLI binary publishes to crates.io as **`eddacraft-kindling`** because the
> bare `kindling` name is taken; the installed command is still `kindling`.

## 1. crates.io

Publishing readiness (done in-repo by PORT-014):

- Each crate that embeds the cross-language schema contract vendors a
  **committed copy inside the crate dir** (`crates/kindling-store/schema/` and
  `crates/kindling-client/schema/`) and `include_str!`s the local copy. The
  repo-root `schema/` remains the canonical cross-language source; the crate
  copies are regenerated by [`scripts/sync-vendored-schema.sh`](../scripts/sync-vendored-schema.sh)
  and a CI drift gate (`vendored-schema` job in `rust.yml`) fails if they drift.
- Every intra-workspace path dependency carries an explicit
  `version = "0.0.1"` (crates.io rejects path-only deps).

**Credential-gated maintainer steps:**

1. `printf '%s' "$TOKEN" | cargo login` (token from stdin; or export
   `CARGO_REGISTRY_TOKEN`).
2. Run [`scripts/publish.sh`](../scripts/publish.sh) — it publishes in
   dependency order: `kindling-types → kindling-store → kindling-provider →
kindling-service → kindling-server → kindling-client → eddacraft-kindling`
   (server publishes before client because client carries a versioned
   dev-dependency on server). crates.io needs a few seconds to index each crate
   before the next dependent one resolves; the script pauses between publishes.

> `cargo publish --dry-run` of a dependent crate fails with
> `no matching package named ...` until its deps are actually on crates.io. That
> is expected for a not-yet-published workspace and is **not** a packaging
> problem — packaging is verified with `cargo package --list -p <crate>`.

## 2. `curl … | sh` installer

The installer lives at the **repo root** ([`install.sh`](../install.sh)) — it is
the single `curl | sh` entry point. It detects OS/arch, resolves the latest
release (or `KINDLING_VERSION`), downloads the matching archive + `.sha256`,
**verifies the checksum**, installs `kindling` to `KINDLING_INSTALL_DIR`
(default `~/.local/bin`), offers to run `kindling init` (with optional Claude
Code setup), then offers to load sample memory with `kindling demo` (skipped
without a terminal or when `KINDLING_NO_DEMO=1`). If no prebuilt binary matches the platform it falls back to
`cargo install eddacraft-kindling`. Linux (x86_64/aarch64, gnu + musl), macOS
(x86_64/aarch64), and Windows (x86_64, `.zip`) are covered.

**Credential-gated / infra maintainer steps:**

1. Cut a GitHub Release so `release.yml` attaches the assets the script
   downloads.
2. Until/unless a dedicated vanity domain is set up, users run the installer
   straight from the repo:
   `curl -fsSL https://raw.githubusercontent.com/eddacraft/kindling/main/install.sh | sh`.

## 3. GitHub Release assets

Publishing a GitHub Release runs [`release.yml`](../.github/workflows/release.yml),
which attaches the 7 target archives and their `.sha256` sidecars, plus the
editor extension as `kindling-<version>.vsix` (with its own `.sha256`). The VSIX
bundles the thin TypeScript client from `packages/kindling`, so editor users need
nothing from npm.

> **Not published to npm (D-010).** kindling stopped publishing to npm. The
> `@eddacraft/*` packages on npm are the retired 0.1.x TypeScript engine and are
> being deprecated with [`scripts/deprecate.sh`](../scripts/deprecate.sh). The
> packages under `packages/` are `private` and live on as source, bundled into
> the VSIX (and, later, into the OpenCode plugin the binary installs).

## 4. Homebrew (`eddacraft/tap`)

The shared tap at [github.com/eddacraft/homebrew-tap](https://github.com/eddacraft/homebrew-tap)
already ships **anvil** (`brew install eddacraft/tap/anvil`). kindling joins the
same tap: publish [`packaging/homebrew/kindling.rb`](./homebrew/kindling.rb) as
`Formula/kindling.rb`.

**Per-release (automated):** `release.yml` opens a PR in `eddacraft/homebrew-tap`
after assets upload. Requires the `HOMEBREW_TAP_TOKEN` secret on this repo (see
[`packaging/homebrew-tap/README.md`](./homebrew-tap/README.md)). Merge that PR to
publish the formula.

**Manual fallback:** `./scripts/generate-homebrew-formula.sh vX.Y.Z --sync-tap`
then push or PR to `eddacraft/homebrew-tap`.

## Maintainer checklist (per release)

- [ ] Tag `vX.Y.Z` on `main` and publish a GitHub Release → `release.yml`
      attaches all target archives + `.sha256` sidecars and the VSIX.
- [ ] `printf '%s' "$TOKEN" | cargo login` + `scripts/publish.sh` → crates.io
      (`cargo install eddacraft-kindling`).
- [ ] Merge the automated `homebrew-tap` PR (or run `./scripts/generate-homebrew-formula.sh vX.Y.Z --sync-tap` manually).
