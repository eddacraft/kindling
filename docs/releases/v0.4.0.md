# kindling 0.4.0

Integration-hardening release. Closes out the post-0.3 downstream-integration
work the daemon/client contract needed before anvil could depend on it in
anger: redaction evidence, published fixtures, an authenticated TCP transport,
atomic capsule close, honest `--db` routing, outage spooling that stays flat
under a deep backlog, and composite scope indexes for keyset reads. It also
carries the CodeQL path-injection fix and the cleartext-logging triage.

> **Breaking** for `kindling-server` (`build_router` gains a `tcp_secret`
> argument), for mixed-version TCP deployments (the daemon now requires a
> bearer token on loopback TCP), and for the schema contract (v5 to v6).
> Pre-1.0, a breaking change bumps the minor, hence 0.4.0.

> **First npm release of the thin client.** This is the first GitHub Release
> since v0.1.2, so it is the first one to run `publish.yml` and `release.yml`
> for the Rust-canonical packages. npm `@eddacraft/kindling` moves from the
> retired 0.1.2 TypeScript implementation straight to 0.4.0, and the prebuilt
> `kindling` binaries are attached to a Release for the first time.

## Highlights

- **Authenticated loopback-TCP transport** (KINTEG-010). The daemon mints a
  per-daemon secret, stores it in an owner-only token file beside the port
  file, and rejects every request except `GET /v1/health` that does not carry
  it as a bearer token. The client reads the token automatically. UDS is
  unchanged.
- **Redaction evidence** (KINTEG-006). Append responses report how many
  secret matches were masked and which classes matched, never the values, so a
  consumer can prove sensitive content was handled without re-leaking it.
- **Published hook-payload fixtures** (KINTEG-007). A versioned
  `fixtures/hook-payloads/claude-code.json`, also exported from
  `@eddacraft/kindling` as `./fixtures`, gives adapter authors a stable
  artefact to test against. The export-bundle compatibility guarantee is now
  documented in `docs/data-model.md`.
- **Flat outage spooling** (KINTEG-013). `SpooledClient` no longer rescans or
  rewrites the whole backlog per append, and backs off a known-unavailable
  daemon instead of retrying on every observation.
- **Composite scope indexes** (KINTEG-014, schema v6). Keyset list queries over
  a repo or session no longer sort through a temporary B-tree.
- **Correctness fixes**: capsule close is atomic when the summary is missing
  (KINTEG-011); `--via-daemon` with `--db` is rejected instead of silently
  routing to a different project's database (KINTEG-012).
- **Security**: database paths are validated before anything is created on
  disk (CodeQL `rust/path-injection` #15); the `rust/cleartext-logging` alerts
  #11 to #14 are triaged as false positives with a CodeQL model pack and a
  written disposition in `SECURITY.md`.

## Breaking changes and upgrade

- **TCP transport requires a bearer token.** A 0.3 client talking to a 0.4
  daemon over TCP (the Windows default) receives 401. Upgrade the client and
  the daemon together. No configuration changes: the token file is derived
  from the existing port-file rendezvous.
- **`kindling_server::build_router(state, tcp_secret)`.** Pass `None` when
  embedding the router over UDS only.
- **Schema v5 to v6.** Read-write opens migrate in place on first open.
  Read-only opens of v5 databases still work. A v6 database cannot be opened
  by a 0.3 engine, so do not downgrade after the first open.

## Install

```bash
# Rust SDK (daemon-backed), with the durable-emit spool
cargo add kindling-client@0.4 --features spool

# one-dependency embedded runtime
cargo add kindling-runtime@0.4

# CLI binary
cargo install eddacraft-kindling@0.4

# npm thin client (bundles the binary via per-platform optionalDependencies)
pnpm add @eddacraft/kindling@0.4

# install script (resolves the latest GitHub Release)
curl -fsSL https://raw.githubusercontent.com/eddacraft/kindling/main/install.sh | sh
```

## Notes

- The Rust crates are published to crates.io separately via
  `scripts/publish.sh` in dependency order (types, store, provider, service,
  server, client, runtime, kindling). `kindling-bench` is `publish = false`.
- Publishing this GitHub Release triggers `publish.yml` (npm packages and
  per-platform binary packages) and `release.yml` (binary archives attached to
  the Release, plus the automated `homebrew-tap` PR, which needs the
  `HOMEBREW_TAP_TOKEN` secret).
